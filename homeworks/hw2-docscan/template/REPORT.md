## 2. Три вопроса

**2.1. На каких кадрах выигрывает путь контуров, на каких — Хаф + RANSAC, и почему? Что общего у кадров, где проигрывают оба?**
- **Путь контуров выигрывает** на кадрах с чёткой, непрерывной границей листа и высоким контрастом к фону, где морфологическое закрытие успешно смыкает контур. Примеры: `05.jpg` (IoU 0.963) и `12.jpg` (IoU 0.976). На этих кадрах `contour` срабатывает мгновенно (~14 мс), находя крупнейший выпуклый четырёхугольник, и режим `auto` даже не запускает тяжёлый RANSAC.
- **Путь Хаф + RANSAC выигрывает** на кадрах, где граница листа частично перекрыта, разорвана тенью или сливается с фоном, но сохранились длинные прямолинейные отрезки. Примеры: `04.jpg` (IoU 0.985) и `15.jpg` (IoU 0.989). Здесь `contour` даёт 0.0, так как контур не замкнулся или был фрагментирован, но RANSAC успешно восстановил 4 доминирующие прямые из оставшихся отрезков Хафа.
- **Общее у кадров, где проигрывают оба** (например, `06.jpg`, `07.jpg`, `08.jpg`, `11.jpg`, `14.jpg`, `17.jpg` при настройках по умолчанию): на них алгоритм `auto_canny` выдаёт 0 пикселей краёв (`edge_pct = 0.0`, `segments = 0`). Без карты краёв не может работать ни один из двух путей. Это происходит из-за сбоя правила медианы на кадрах с высокой общей яркостью.

**2.2. Правило медианы для порогов Canny: на скольких кадрах из пятнадцати сработало, где и почему ошиблось, что показала фиксированная пара? Что вы оставили в своём сканере?**
- **Статистика:** Из 15 кадров с листом правило медианы дало адекватные пороги (позволяющие найти лист) примерно на 8–9 кадрах. 
- **Где и почему ошиблось:** На 6–7 кадрах правило дало полный отказ (0 краёв). Причина: формула `hi = 1.33 * median` привязывает порог к *абсолютной яркости* кадра. На светлых кадрах (медиана ~150) верхний порог достигает ~200, что выше реального градиента на границе листа, и Canny игнорирует край.
- **Фиксированная пара (50, 150):** При запуске `eval` с `--canny 50,150` количество успешно найденных листов методом `hough` выросло с 8 до 13, а средний IoU подскочил с 0.527 до 0.858. Фиксированный перепад яркости надёжно выделяет границы независимо от общего освещения кадра.
- **Итоговый выбор:** В качестве основной настройки для сканера я оставляю **`--canny 50,150`**, так как она обеспечивает максимальную надёжность и предсказуемость на разнородном наборе данных, устраняя главный источник отказов авто-порогов.

**2.3. Шум и текст: какая σ шума у ваших кадров при разном свете, какую σ фильтра выбрала программа, сошёлся ли остаток с формулой? Что меняет закрытие текста — в числах?**
- **Оценка шума:** На кадрах при дневном свете σ шума составила ~2.1–7.1, при лампе ~0.7–4.2, в полумраке ~0.5–1.7. (Высокие значения днём могут быть связаны с высокой текстурой фона, которую ядро не полностью подавило).
- **Выбор фильтра и формула:** Программа рассчитывала `σ_f` по формуле из L5. Для целевого остатка в 1 код яркости и шума ~10 программа выбирала `σ_f ≈ 1.6`. Измеренный остаточный шум после фильтрации (например, 0.98) практически идеально сошёлся с предсказанным по формуле значением (1.01), что подтверждает корректность модели. При сильном шуме программа упиралась в ограничение `hi=3.0`, жертвуя идеальным подавлением шума ради сохранения резкости углов.
- **Закрытие текста (`--close 9` против `--close 0`):** В числах это выглядит как взрывной рост сложности. Например, на кадре `04.jpg` отключение закрытия увеличило долю краёв с 2.34% до 8.55%, а число отрезков Хафа — с 24 до 312. На кадре `16.jpg` отрезков стало 481 вместо 35. Закрытие ядром 9×9 стирает высокочастотный текст, оставляя RANSAC только низкочастотные границы листа, что критически важно для успешного отбора 4 доминирующих прямых.

## 3. Негативные кадры и отказы

- **Кадр `01.jpg` (нет листа):** Программа ответила «не найдено» (`contour_found: False`, `hough_found: False`). Это корректный отказ, так как в кадре отсутствовали объекты, похожие на прямоугольный лист с достаточным контрастом.
- **Кадр `02.jpg` (нет листа):** Аналогично, все методы вернули `False`. Корректный отказ.
- **Кадр `03.jpg` (нет листа):** Программа **ошибочно нашла лист** (`contour_found: True`, `auto` выбрал путь `contour`). Причина: в кадре присутствовал другой прямоугольный предмет (например, книга или планшет), контур которого оказался крупнейшим и выпуклым, а эвристика `looks_like_paper` не смогла его отфильтровать (яркость внутри и снаружи объекта была сопоставима).
- **Отказ на кадре с листом (`07.jpg`):** 
  - *Что получилось:* IoU = 0.0 (лист не найден ни одним методом).
  - *Причина:* Сбой правила медианы Canny. Из-за высокой яркости кадра пороги оказались завышенными, карта краёв пуста (`edge_pct = 0.0`).
  - *Что бы помогло:* Принудительное использование фиксированных порогов `--canny 50,150`. Как показал тест `eval_50_150.csv`, эта настройка успешно находит лист на подобных кадрах, так как опирается на реальный градиент, а не на среднюю яркость.

## 5. Команды

Всё, что лежит в `out/`, получено этими командами (скопируйте из консоли):

```bash
# 1. Разметка углов

# 2. Оценка шума и краёв (примеры для отчёта)

python docscan.py edges data/04.jpg -o out/04_edges_def.png
python docscan.py edges data/04.jpg --close 0 -o out/04_edges_noclose.png
python docscan.py edges data/04.jpg --canny 50,150 -o out/04_edges_fixed.png

# 3. Основная оценка набора (IoU и время)
python docscan.py eval data --ann data/corners.json --seeds 20 --csv out/eval.csv --overlays out/eval
python docscan.py eval data --ann data/corners.json --seeds 20 --canny 50,150 --csv out/eval_50_150.csv --overlays out/eval_50_150
python docscan.py eval data --ann data/corners.json --seeds 20 --close 0 --csv out/eval_noclose.csv --overlays out/eval_noclose

# 4. Бинаризация (демо курса и свой кадр с тенью)
python docscan.py binarize lectures/L03-color-histograms/demo/L3/text-lamp.png --method all --gt lectures/L03-color-histograms/demo/L3/text-gt.png -o out/text-lamp_bw.png
python docscan.py binarize data/06.jpg --method otsu -o out/06_otsu.png
python docscan.py binarize data/06.jpg --method adaptive -o out/06_adaptive.png
python docscan.py binarize data/06.jpg --method flat -o out/06_flat.png

# 5. Выпрямление и сканирование (примеры)
python docscan.py scan data/05.jpg -o out/05_scan.jpg --bw out/05_bw.png
python docscan.py scan data/15.jpg --turn 1 -o out/15_scan.jpg

# 6. Видеорежим (запись 10 секунд с камеры или файла)
python docscan.py video --source 0 --method auto --seconds 10 --save out/video.mp4
# (Для тестов также использовался файл: python docscan.py video --source data/clip.mp4 --method auto --no-window --seconds 0)
```
